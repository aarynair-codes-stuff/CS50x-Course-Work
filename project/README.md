#### Description:
## Signup
The signup page has been fully implemented with a GUI that almost fully matches the initial design. A file has been created which would allow me to create session variables which will be useful in storing the user’s user id when querying the database. The input fields for the signup system are generated by an algorithm (signup_inputs) which retains the username entered by the user if it was valid which is a useful usability feature. Furthermore, validation algorithms for the input data have been implemented which allow for the input data to be checked for length or compared against the database for example and which output error messages when the input data is invalid. Furthermore, if the credentials are valid, a success message is output, and the data is stored in the database.
## Login
The login page has now been fully implemented with a GUI which almost exactly matches the design created during the design stage. The login page can validate the input data once the submit button is clicked, in the login.inc.php file. There, various validation functions check if the input credentials are valid or not and output corresponding success/error messages. I have also implemented a function which outputs a hello message upon successful login which is a nice usability feature. I have also identified a database connection error which is caused by leaving XAMPP running in the background of the computer without terminating the database connection.
## Calendar
The calendar page is now complete and functional. A month selector has been implemented which outputs the month data to a div underneath the selector. The month data is correctly output according to the 2026 calendar with a heading, a header row which states the day of the week, and the day buttons. Each button is a submit button for an individual form element and hidden input which redirects to the input form with the date as a get value. The date value has been correctly formatted for each button so that the value is of a suitable format for use with the MySQL database. Furthermore, the code allows for checking for events with colour coding for which it adds classes to the day cell for it to be styled. The multiple replace_(month name) functions have been replaced with a single replace_month function and a dictionary called calendarData which allows for modularity and scalability as data for more years can be stored using further nesting of dictionaries. The areas which would need to be changed for future maintenance have been highlighted with the changes stated so that future developers can expand the calendar data.
## Input Form
The input form has been fully implemented. Each input has been declared according to the design (input field for the event name, textarea for event description, checkboxes for skills and radio buttons for tags). The input field successfully sends data to the ‘inputform_input.inc.php’ file which performs validation on the input data. An error message is output if the event name field is blank, but a success message is output if the input data was inserted into the database successfully. The ‘inputformhandler.inc.php’ file allows for the values of the input fields to retain the values stored in the database when the day cell is clicked, and the values can be updated upon the submit button being pressed. Furthermore, the page has been designed to match the planned design from the design stage of the project using CSS.
## Skills
The skills page has been implemented according to the planned design. The rounded divs and separation by skills have been implemented using a table as a grid. The example descriptions have been implemented for each skill, and the alternating design is present throughout the page. The page creates the textareas and each textarea retains the data inserted in the database using the output_skills function which combines the functions which retrieve the data from the database and create the textareas based on the data. This function can be called in the skills page which makes the design modular in nature as any changes to the previous functions can be implemented in the output_skills function without needing to change anything on the skills page. Furthermore, the formhandler has been implemented which stores the input data in the database and produces a success message. This is helpful for usability as the user has a clear message informing them of a successful input. Finally, a navigation bar has been implemented which will be included on all pages except for the account creation pages to allow the user to traverse between pages of the program easily which is a good usability feature. The navigation bar also contains a button for logout which unsets all of the session variables and redirects the user to the login page. This allows the user to logout of the website without needing to close the tab. This makes the program feel more robust and similar to other modern websites.
## Timeline
The timeline page has been fully implemented. The GUI of the page has been correctly styled according to the design present in the design stage of the program using the same arrow image used in the initial design. All of the event names and dates are output as titles alongside textareas for event reflections using the output_events function in timeline.inc.php. This file as a whole is modular in nature as it uses the same create_text_areas and get_data functions present in skills.inc.php but with changes which allow the program to be suitable for the timeline page. The event reflection textareas contain the values inserted in them in the database upon creation. These values can be inserted/updated in the database by changing the values and pressing the submit button which sends the data to a formhandler which validates the data before it is sent to the database. The save as pdf desirable feature has also been implemented which allows the user to have a copy of the timeline page to attach to their cv or use as reference.
